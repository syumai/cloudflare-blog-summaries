理解度テスト: AIエージェントに必要なのはコンテナではなくコンピューター —「@cloudflare/computer」のご紹介

全9問。基本→応用の順に並んでいます。すべて回答したら「採点する」ボタンを押してください。

Q1.記事における「アイソレート」の特徴として正しいものはどれか。

正解: C
アイソレートは、Workers（約10年前）・Durable Objects（約6年前）から投資されてきた技術で、 ほぼ無限に近い水平方向のスケール拡張に対応でき、非常に高速に起動・終了できる。アイドル時には 休止状態（ハイバネーション）に入り状態を保持したままリソース消費を抑えられる、と記事にある。 A・B・Dは「コンテナ型」バックエンドの特徴であり、アイソレートとは逆。

Q2.@cloudflare/computerが提供する標準ツール（AI SDK互換のツールキット）に含まれないものはどれか。

正解: B
記事では、よく使用される基本的なツールとして read・write・edit・ ls・exec の5つが標準ツールとして挙げられている。deployという 名前の標準ツールは記事中に登場しない。

Q3.Workspace（仮想ファイルシステム）がバックエンドに使用している技術は何か。

正解: A
記事では「ワークスペースは、SQLiteをバックエンドに使用した仮想ファイルシステムで、クラウドストレージ やソースコード管理システムなど、さまざまなソースから内容を取り込むことができます」と説明されている。

Q4.@cloudflare/computerの公開形態について、記事の内容として正しいものはどれか。

正解: D
記事では「本日、私たちは@cloudflare/computerの初期プレビュー版を公開します」と述べられ、 github.com/cloudflare/computer でOSSとして公開されている。利用開始には npm install @cloudflare/computer を実行する。

Q5.コンテナ型バックエンドについて正しいものはどれか。

正解: C
記事では「コンテナ型：Cloudflare Containersを使用して、完全なLinux環境を提供し、ファイルシステムは Filesystem in Userspace（FUSE）としてマウントされる」と説明されている。A・Bはアイソレート型（just-bash） の説明であり、Dは実際には逆（アイソレートの方が高速起動）。

Q6.Cloudflareが、AIエージェントの実行基盤として「コンテナだけ」ではなく「アイソレート」を重視する最大の理由は何か。

正解: B
記事の背景・課題セクションで「世界中のすべての企業が、自社ユーザーのAIエージェント1つひとつに専用の コンテナ型コンピューティング環境を提供できるほどの計算資源は存在しません」「数億、さらには数十億もの AIエージェントを稼働させる規模には対応できない」と述べられている。アイソレートは高速起動・ ハイバネーション・ほぼ無限の水平スケールによってこの制約を回避する。

Q7.モデルが実行バックエンド（アイソレート／コンテナ）を自動選択する仕組みについて、記事の説明として正しいものはどれか。

正解: A
記事では「ツールの説明には、現在のタスクに適した実行ランタイムをAIエージェントが選択できるような情報 が含まれ」「最先端のAIモデルはこの判断を非常に高い精度で行い、本当に必要な場合にのみコンテナを利用」 すると説明されている。コード例③でも、コンテナのツール説明文に「npm, node, package managers, test runners, and real binaries on $PATHが必要なときに使え」という文言が埋め込まれている。

Q8.アイソレートとコンテナ間のファイルシステム共有について、記事の説明として正しいものはどれか。

正解: D
記事では「アイソレートとコンテナが同じファイルシステムを共有して作業を行い、各環境で変更された内容は、 元となるファイルシステムと常に同期されます」と説明されている。これにより、タスクの前半をアイソレート、 後半をコンテナで実行するといった切り替えがファイルの一貫性を保ったまま行える。

Q9.（コード読解）以下のコードは、コード例①のアイソレート専用エージェントに対して追加された変更である。この変更が実現していることとして最も適切なものはどれか。

export class Agent extends withWorkspaceContainer(Think) {
  override workspaceBash = false;

  override workspace = new Workspace({
    storage: this.ctx.storage,
    useThink: true,
    backends: [
      new CloudflareContainerBackend({
        container: () => this,
        workspace: {
          binding: "Agent",
          id: this.ctx.id.toString(),
        },
      }),
    ],
  });
}
正解: C
withWorkspaceContainer(Think)というミックスイン形式のクラス拡張でコンテナのライフサイクル 管理機能を追加し、backends配列にCloudflareContainerBackendを渡すことで、 Workspaceはアイソレート（デフォルト）に加えてコンテナも実行先として認識するようになる。 workspace.bindingとworkspace.idは、どのDurable Object（エージェント インスタンス）に紐づくコンテナかを一意に特定するための情報。アイソレートを無効化するものではなく、 両方を使い分けられるようにする変更である（A・B・Dはいずれも誤り。ツール統合のreplyToIssue はコード例③で追加される別の変更）。
